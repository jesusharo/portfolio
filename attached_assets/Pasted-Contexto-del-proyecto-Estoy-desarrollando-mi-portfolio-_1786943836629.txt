Contexto del proyecto

Estoy desarrollando mi portfolio en Replit con Next.js. El proyecto vive únicamente en Replit por ahora — todavía no hay repositorio en GitHub ni despliegue en Vercel. Actualmente tiene dos vistas principales tipo grid:

Proyectos UI — grid de tarjetas cuadradas con esquinas redondeadas, cada una con un color de fondo distinto y un logo/isotipo centrado.
Case studies — misma estructura de grid, pero enlaza a páginas de detalle de caso de estudio con hero image y contenido largo (texto + imágenes), como muestra el ejemplo adjunto de "Atentu".

Ambas vistas comparten un dock de navegación fijo a la izquierda con iconos (editar, guardar/bookmark, IA/sparkle, historial, correo).

Necesito construir un editor de contenido propio (no un CMS de terceros) para poder agregar y administrar proyectos y case studies sin tocar código, protegido con mi correo personal.

Objetivo

Construye un editor de contenido en forma de drawer lateral (panel deslizable) que se abre desde el ícono de editar/pen del dock existente, con las siguientes capacidades:

1. Autenticación
El editor solo debe ser accesible para mí, autenticado con mi correo personal. Usa Replit Auth si está disponible como integración nativa; si no aplica bien a un login por correo específico, usa magic link por email o un passcode simple guardado en Replit Secrets — la opción que sea más rápida de implementar.
El resto del portfolio (grids, páginas de detalle) permanece público, sin login.
Si alguien sin sesión intenta acceder a las rutas del editor, redirige al portfolio normal sin mostrar ningún control de edición.
2. Modelo de datos

Necesito una entidad Proyecto reutilizable tanto para "Proyectos UI" como para "Case studies" (mismo modelo, distinta colección/tag):

Project {
  id
  type: "ui_project" | "case_study"
  name: string
  slug: string (autogenerado del name, editable)
  order: number
  hidden: boolean
  backgroundColor: string (hex, seleccionable con color picker)
  logoGridImage: image (logo para la tarjeta en el grid)
  logoHeaderImage: image (logo para el header de la página de detalle)
  heroImage: image
  contentBlocks: ContentBlock[]
}

ContentBlock =
  | { type: "richtext", html: string }
  | { type: "image", url: string, caption?: string }
3. UI del editor (drawer)
El drawer se abre desde el ícono de editar del dock, sobre cualquier vista del portfolio.
Tiene dos tabs o secciones: Proyectos UI y Case Studies (mismo componente, filtrado por type).
Dentro de cada sección:
Lista de proyectos existentes, reordenable por drag & drop (actualiza el campo order).
Cada ítem de la lista muestra: nombre editable inline, un toggle de ocultar del grid (hidden), y un botón para entrar al editor de detalle de ese proyecto.
Botón "+ Nuevo proyecto" al inicio o final de la lista.
Editor de detalle de un proyecto (dentro del mismo drawer o en un segundo nivel):
Selector de color de fondo (color picker).
Upload de logoGridImage.
Upload de logoHeaderImage.
Upload de heroImage.
Editor de contentBlocks: debe permitir agregar bloques de texto enriquecido (bold, italic, listas, títulos, enlaces) y bloques de imagen, en el orden que yo decida, con posibilidad de reordenarlos, editarlos o eliminarlos.
Un botón fijo de "Guardar cambios" al fondo del drawer que persiste todo lo editado en esa sesión (no autosave por campo — cambios locales hasta que confirme).
4. Sección "About me"
Dentro del mismo editor, agrega una sección aparte (no ligada a un proyecto) para editar el contenido de mi página "About me", con el mismo tipo de editor de texto enriquecido usado en los contentBlocks.
También debe guardarse con el botón de "Guardar cambios".
5. Consideraciones técnicas
Next.js (App Router). El proyecto vive actualmente solo en Replit — todavía no hay repositorio en GitHub ni despliegue en Vercel, así que puedes usar libremente las integraciones nativas de Replit sin preocuparte por compatibilidad inmediata con producción.
Para almacenamiento de imágenes, usa la integración de Object Storage de Replit.
Para persistencia de datos (proyectos, case studies, about me), usa la base de datos PostgreSQL integrada de Replit.
El editor de texto enriquecido puede ser una librería ligera (ej. Tiptap) que guarde el contenido como HTML o JSON serializable.
El grid público y las páginas de detalle deben leer directamente de esta base de datos (no de archivos estáticos), respetando order y hidden.
No necesito versionado ni historial de cambios por ahora — solo el estado actual.
Usa Replit Secrets para cualquier variable de entorno o credencial.
Nota para más adelante (no bloquea el desarrollo ahora): cuando llegue el momento de subir esto a GitHub y desplegar en Vercel, habrá que revisar si el Object Storage y el PostgreSQL de Replit siguen siendo accesibles desde Vercel o si conviene migrar a algo portable (Neon, Supabase, Vercel Blob/Postgres). Por ahora, prioriza avanzar rápido dentro de Replit.
6. Criterios de aceptación
 Puedo iniciar sesión con mi correo y acceder al drawer del editor; nadie más puede.
 Puedo crear un proyecto nuevo, asignarle color, subir sus 2 logos y su hero image.
 Puedo agregar bloques de texto enriquecido e imágenes al contenido del proyecto, en el orden que quiera.
 Puedo reordenar los proyectos del grid arrastrándolos en el drawer.
 Puedo ocultar un proyecto del grid sin borrarlo.
 Puedo renombrar un proyecto desde el drawer.
 Esta misma funcionalidad aplica igual para "Proyectos UI" y "Case studies".
 Puedo editar el contenido de "About me" desde el mismo editor.
 Los cambios solo se guardan cuando presiono "Guardar cambios".
 El grid público y las páginas de detalle reflejan los cambios guardados, sin necesidad de redeploy.
